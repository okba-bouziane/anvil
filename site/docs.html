Documentation

Pitoo is a free, open source code editor. It works with no account, no AI and no internet. Everything here applies to Mac, Windows and Linux unless it says otherwise.

Install

Mac

  1. Download the Mac file from the download section. It's for Apple Silicon.
  2. Unzip it and move Pitoo to Applications.
  3. The app isn't notarized by Apple yet, so run this once in Terminal:
xattr -cr /Applications/Pitoo.app

Windows

Run the installer. It isn't signed yet, so SmartScreen may warn you. Choose More info, then Run anyway.

Linux

Use the AppImage, which needs no install, or the deb package:

chmod +x Pitoo-linux-x86_64.AppImage
sudo apt install ./Pitoo-linux-amd64.deb

Updates

When a new version is out, an Update button appears at the top of the window. It downloads the new version, then offers to restart. You can turn the check off in Settings, under Editor.

First steps

  1. Open a project, clone a repository, or open a workspace from the start screen.
  2. Press ⌘P to open a file. On Windows and Linux, use Ctrl wherever this page shows ⌘.
  3. Press ⇧⌘P to see every command in one list.
  4. If you don't want AI, press ⌘L to hide the agent. Nothing else depends on it.

Your open tabs come back the next time you open a project.

The editor

Pitoo uses Monaco, the same editing engine as VS Code, so multiple cursors, find and replace, code folding and most editing shortcuts work the same way.

  • Side by side: press ⌘\ or right-click a tab and choose Open to the side. Drag the divider to resize, and double-click it to reset.
  • Tabs: drag to reorder, middle-click to close, right-click to close others. ⇧⌘T reopens the last one.
  • Panels: drag any panel edge to resize it, and double-click to go back to the default size. ⌘B hides the side panel.
  • Zen mode: shows only the code. Choose it from the View menu, and press Escape to leave.
  • Previews: images open as pictures, and Markdown files have a Preview button.
  • Saving: auto-save is on by default. Turn it off in Settings, under Editor.
  • Margin marks: show lines that differ from your last commit.

Font size, cursor style, tab size, word wrap, minimap, sticky scroll and file icons are all in Settings (⌘,).

Windows and workspaces

New window: press ⇧⌘N to open another project in its own window.

Workspace: several folders open together, such as a frontend and a backend in separate repositories. Choose File, then Add Folder to Workspace. Save it with File, then Save Workspace As. Pitoo reads and writes the same .code-workspace files as VS Code.

Only the folders you add can be seen or changed, including by the agent. If they hold separate repositories, a menu at the top of the Git panel switches between them.

Terminal command: on Mac and Linux, run Install the pitoo terminal command from the command palette. Then pitoo . opens any folder.

Search

Press ⇧⌘F to search the project. You can match case, match whole words or use a regular expression. Choose Filter by files to limit it, for example to src/** or to leave out *.spec.ts.

Replace all shows every replacement in the changes list above the chat, so you can review and undo them.

Terminal and tasks

Press ⌘J for the terminal. It has tabs and can split in two. File paths and addresses in the output can be clicked, such as src/app.ts:12 in an error.

The Scripts tab runs npm scripts with one click. Run Task, in the Terminal menu, also lists tasks from .vscode/tasks.json.

Git

Open the Git tab in the side panel. Git must be installed on your computer.

  • Commit: stage files or stage a single block from the compare view, then commit. Turn on Amend to change the last commit.
  • Sync: Fetch, Pull and Push. The ⋯ menu has pull with rebase and safe force push. Pushing a new branch sets its upstream for you.
  • Branches: click the branch name to switch, create, rename, delete, merge or rebase. Remote branches are listed too.
  • Stash: set work aside and bring it back later, including new files.
  • Commit history: every branch as a graph. Click a commit to see its files, or right-click to branch, tag, cherry-pick, revert or reset.
  • Who changed this line: shown at the end of the line you're on, and File history is above the editor.

Resolving a conflict

  1. When a merge or rebase stops, the panel shows Merging or Rebasing, with the files to fix.
  2. Open a file. Each conflict has Keep current, Keep incoming and Keep both, and you can also edit by hand.
  3. Save, then press the check mark beside the file to mark it resolved.
  4. Press Continue, or Abort to go back to how things were.

Pull requests

These use GitHub's gh tool. Install it and run gh auth login once. Pitoo then lists, checks out and creates pull requests, and never sees your GitHub password or token.

ESLint and Prettier

If your project uses them, Pitoo asks once whether to allow them. It runs your project's own installed versions with your own config, the way VS Code does, and that means running code from the project. Only allow it for projects you trust.

Once allowed, ESLint problems appear as you type, with quick fixes. Prettier handles Format and format on save. Fix ESLint problems on save is in Settings. In a monorepo, each package uses its own config.

Debugging

Click beside a line number, or press F9, to add a breakpoint. Then open the Debug tab, choose what to run, and press Start.

  • This file: runs the open JavaScript, TypeScript or Python file.
  • npm run: debugs any npm script, including child processes. TypeScript breakpoints work through source maps.
  • Open in Chrome: debugs a web app at an address you give.
  • Attach: connects to a Node process already running with --inspect.
  • launch.json: setups from .vscode/launch.json appear in the same list.

While paused you have the call stack, variables, watch expressions and a console. F5 continues, F10 steps over, F11 steps in and ⇧F11 steps out. To stop only in some cases, add a condition to a breakpoint from the list.

Python debugging needs debugpy in your Python:

python3 -m pip install debugpy

Extensions

Press ⇧⌘X to browse Open VSX, the open extension registry. Each extension is labeled:

  • Works in Pitoo: color themes and snippets. These install and work.
  • Partly works: its themes or snippets work, and the rest of it doesn't.
  • Can't run yet: a program, such as a language pack or GitLens.

Program extensions don't run because they depend on VS Code's internal engine, which Pitoo doesn't have. Pitoo keeps only an extension's data files and never runs its code.

Coming from VS Code

  • Import: Settings, then Editor, then Import from VS Code copies your settings, snippets and color themes.
  • Project files: Pitoo follows editor settings in .vscode/settings.json, and reads tasks.json, launch.json and .code-workspace files.
  • Shortcuts: the main ones match. See the list below, or Keyboard Shortcuts in the File menu. They can't be changed yet.

AI models

AI is optional. Open Settings, choose a provider, and press Use.

The chat box always shows where your code goes. If you run a local model and want its full speed, turn on Leave the graphics chip to the local model in Settings. Scrolling is then less smooth.

The agent

  • Agent: reads, edits and runs commands.
  • Plan: can only read, and proposes what to do.
  • Ask: answers questions, with no tools.

Type @ to attach a file. Put your project's rules in PITOO.md, ANVIL.md or AGENTS.md and the agent follows them. Each project keeps its own chats, which survive a restart.

Commands ask before they run. Once approved, a command has your full user permissions and can't be undone from Pitoo, so leave Auto-run commands off unless you trust the project.

Working with the agent

  • Type while it works: press Enter and your message waits, then goes out when the agent finishes. Choose Send now and the agent reads it before its next step.
  • Protect secrets: the agent can't open, list or search .env files, private keys and similar files. Add your own patterns to a .pitooignore file in the project, and use ! for exceptions. A command you approve can still read any file, and a file you attach with @ is sent.
  • Import sessions: open the chat list and choose Import sessions to bring in your local Claude Code conversations. Messages and answers come across. Tool results and earlier edits don't.
  • Claude Code: the Claude Code button opens the official tool in the built-in terminal, with its own sign-in. Pitoo never sees that sign-in. The chat panel uses a local model or an API key.

Reviewing changes

Everything the agent changes goes in the list above the chat box.

  • Closed: shows the totals, with Keep all and Undo all.
  • Open: each file has its own Keep and Undo.
  • Click a file: shows its changes, with Keep and Undo on each block.
  • Undo this step: in the chat, restores every file from a step, even changes you already kept.

Edits are already on disk while you review, so you can run or test them first. Undo puts the file back.

Shortcuts and crash recovery

Open Keyboard shortcuts from the command palette to change any shortcut, see conflicts, or import your VS Code keybindings.json. Two-step shortcuts aren't supported yet.

With auto-save off, Pitoo keeps a local copy of unsaved edits. After a crash it offers to restore them. Settings has its own search box.

Privacy and security

  • No account and no telemetry.
  • With no AI or a local model, your code stays on your computer.
  • With a cloud provider, the code the agent reads and your messages go to that provider.
  • Network use you can turn off or avoid: the update check, the extension store, and Git commands you run.
  • API keys are encrypted with your system's secure storage. On Linux without a keyring, Pitoo refuses to save them.

Troubleshooting

Mac says the app is damaged
Run xattr -cr /Applications/Pitoo.app.
Git says it couldn't sign in
Run the same command once in the terminal to sign in, then try again.
ESLint shows nothing
Check that you allowed it for this project, and that npm install has been run.
Python can't find a package
Allow the project so Pitoo can use its .venv, or install the package in your Python.
The local model feels slow
Close heavy apps and use the graphics chip setting above. See the FAQ for what to expect.
